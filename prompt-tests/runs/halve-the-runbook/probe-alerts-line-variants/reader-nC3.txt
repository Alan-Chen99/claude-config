**`WORKERS=4`.**

That number isn't a tuning choice — it's derived: the vendor pool is 5 connections per tenant, the admin console permanently holds 1, so 4 is what's left. The runbook calls it "a ceiling, not a knob."

Two things worth carrying into the config:

- **Don't go above 4.** Raising it doesn't buy throughput; it contends with the admin console's connection against a hard vendor limit. Note the trap in the 503s line: "503s nearly always pool exhaustion; check `WORKERS` first" means *verify it's still 4*, not *raise it*. If you're seeing 503s, the fix direction is down or unchanged, not up.
- **It's read at boot.** Config changes need a restart to take effect, not a reload — which also means it interacts with the `./migrate.sh` ordering (column adds before the restart, drops/renames after the roll).

Going *below* 4 is technically allowed by the constraint — it's a ceiling, not a required value — but the runbook gives no reason to, so 4 is the answer.
