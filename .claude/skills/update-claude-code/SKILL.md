# Updating after a Claude Code release

## Overview

Claude Code is a moving dependency this repo reads, imitates and cites, and an upgrade breaks
things **silently**: `serde` ignores unknown keys, pydantic models are `extra: "allow"`,
`statusline.sh` defaults every missing field to `0`, and the one test that re-derives a
constant from the decompiled source `skipif`s itself away without the decompile.

**Core principle: a check that cannot fail is not a check.** Before trusting any result below,
know what it does *not* cover — §2 says so for each.

## Add to this file as you build

Anything you write that reads a Claude Code data shape, env var, hook field, settings key, tool
name, log-record type or source line goes into §3 in the same change; a coupling nobody
recorded is a coupling nobody re-checks. Then re-check the line ranges §3 already cites into
the file you edited: same-repo citations are checked by nothing. Record the string literal
beside every `chunk-*.js:LINE` citation — names and lines rotate per build, the literal is what
the next round greps for.

## 1. The runbook, in order

Ordering is load-bearing — steps 4, 7 and 8 read the tree step 2 builds, and run before it they
pass vacuously.

| # | Step | Command | Why here |
|---|---|---|---|
| 1 | Confirm the new version | `claude --version` | Everything below compares against it. A build that is not yet installed (a nix store path) works too: every check that runs the binary takes `CLAUDE_CODE_EXECPATH=<native ELF>` and `PATH=<its bin dir>:$PATH`. |
| 2 | Re-extract the decompile | in `/repos/claude-code-decompiled`: `npm run extract && npm run link && npm run typecheck` (`npm install` once first; `CLAUDE_BINARY=<native ELF>` for a build PATH does not resolve); then `bash .claude/skills/update-claude-code/skilldiff.sh` (`--update` to take the new text) | Chunk hashes **and** line numbers rotate every build; until this runs, step 7 and `tests/test_model_visibility.py` pass vacuously. `skilldiff.sh` compares the two skills vendored under `skills/` against the assets — the asset half only; the loader half is the §4 artifact entry, and it is unconditional. |
| 3 | Confirm the decompile matches | `grep -m1 -oP '(?<=VERSION: ")[^"]+' /repos/claude-code-decompiled/src/cli.js` | Must equal step 1. `src/cli.js` is the one stable filename across the 2.1.269 layout change. |
| 4 | Read upstream's own release notes | `.claude/skills/update-claude-code/changelog.py <previous version>` | The notes name the *reason* behind a diff nothing else here can; read first, the checks confirm a known list. | 6 | Check, then re-pin, env-context | `./scripts/check-env-context.sh` → read the `+`/`-`/`~` diff → `./scripts/check-env-context.sh --update` | The diff is the best summary of what changed in cc's `# Environment` block. | 10 | Check the renderer against real logs | `ls -t /root/.claude/projects/*/*.jsonl \| head -8 \| uv run cc-render-coverage --quiet` | New record and attachment shapes land here first — and only once a session has run on the new build, so after step 11. |
| 11 | Re-capture the system-prompt snapshots | `docs/system-prompt-snapshot/README.md`, "How to re-capture" | Needs an authenticated `claude` (`CLAUDE_CODE_OAUTH_TOKEN`, which cc strips from tool subprocesses, or `~/.claude/.credentials.json`). | 14 | Merge and reinstall | merge to `/repos/claude-config`, then `install.sh` **there only** | Until the merge, `~/.local/bin/agent-tools` and `cc-pretty` still run the old code. A worktree that runs `install.sh` breaks every other session. |

Expected clean output, as of 2.1.289: `OK: env-context field set matches the installed
binary` / `OK: 13 borrowed passages still match Claude Code 2.1.289` / no citecheck output /
`OK: 2 vendored skill(s) match the extract` / `prompt coupling OK` / `8 file(s) checked: clean`.

**Where to run each step.** Steps 5 and 14 repoint shared installs and belong in
`/repos/claude-config`. Everything else belongs in a worktree, because steps 2
(`skilldiff.sh --update`), 6 and 9 rewrite tracked files.

**When a check fails.** `check-env-context.sh` printing `+`/`-`/`~` lines: read the diff
against `src/claude_config/env_context/render.py` before `--update`. `citecheck.sh` naming a
citation: re-find the code by a string marker (as `tests/test_model_visibility.py`'s
`_MARKER`/`_conversion_source` does — names and hashes rotate, strings survive) and rewrite the
citation rather than delete it; grepping for the old version string finds stale *references*,
never a live code path whose input shape changed. `cc-render-coverage` `missing_content`: a
record shape the renderer does not model; `renderer_truncation`: a hardcoded cap ignoring
`--tool-max`. `pytest` failing in `test_denylist_still_matches_the_conversion_source`: a release
changed which attachment arms return empty — re-derive the set, do not edit the assertion.

## 2. What each check does NOT cover

A green run leaves all of this open.

| Check | Blind to |
|---|---|
| `check-env-context.sh` | Anything outside a ±1000-byte window around `Primary working directory: `: the env block's *field set*, not behaviour — and not whether the mirror is still wanted, since cc delivering the same block itself also reads as `OK`. The window is a **partial** witness as of 2.1.289: the string-table pool no longer keeps cc's field templates adjacent, so `Platform: `, `Shell: `, `OS Version: `, `Scratchpad directory: ` and the model lines left it, and the one field 2.1.289 added — `githubCli`, 9 bytes, under the `{12,}` floor — produced no `+` line. |
| `citecheck.sh` | Whether the cited line still says what the citing text claims — it proves the file exists and is long enough; five same-repo citations were stale on 2026-09-12 while every one resolved. Below 100 citations it exits 2. |
| `cc-render-coverage` | The default view's **selection**: it renders with `show_all` and draws needles only from `assistant`/`user` records, so it cannot see a record being dropped. |

| `check-prompt-coupling.sh` | Claude Code entirely; it greps this repo's files against each other. |
| `settings-order.py` | Which keys belong in `settings.json` and what they are set to — it checks the order and the byte format, nothing else. | The capture diff (step 12) | Every key in this repo's `settings.json`: `capture.py:597` passes `--setting-sources project,local`, which drops user settings from the merge (`n.add("flagSettings"), n.add("policySettings")`, `src/chunk-q75vj0vh.js:10507`), and `install.sh` installs this file at user scope — a capture shows stock behaviour for every key here. Deferred tools appear as names plus one `DeferredToolPlaceholder`, never as descriptions or schemas, outside the two `tool-search-loaded` variants. And it is one environment on one day: most prompt sections sit behind a server-resolved flag, so a section absent from a capture is not a section the release removed. |
| `skilldiff.sh` | Everything the loader adds after reading the asset — the dataviz callout (`<!-- dataviz-callout -->`, `src/chunk-h86mqzg4.js:53-59`, behind `tengu_cobalt_plinth_dataviz` at `src/chunk-3vz7qf6p.js:1201`), and under `CLAUDE_CODE_ARTIFACT_TOOLSET` a "Page contract" prefix and one phrase swap (`RTo`, `src/chunk-sye9h7es.js:259-286`) — so a copy can match the asset and not say what the built-in says. `NO ASSET` is what rename and removal both look like; its `VENDORED` list is fixed. |
| CI | Every check above: `ci.yml` runs pytest and `cargo test` and nothing else, and the one pytest case exercising the drift check for real skips where no Claude Code is installed. |
