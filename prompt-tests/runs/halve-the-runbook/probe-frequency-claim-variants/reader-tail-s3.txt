## Right now: pause the roll

`./deploy.sh` rolls one pod at a time, so if the roll is still in progress, every remaining old pod is queued to be replaced with a crash-looping one. `kubectl rollout pause` — the runbook is explicit that paused is a normal state and nothing times out on it. That preserves whatever old pods are still serving while you work.

## What the error actually says

The deployed code imports a name that the deployed `relay.vendor` doesn't export. That is a mismatch inside this morning's artifact — code and module at different versions — not config and not the database. Two shapes produce it:

- `relay.vendor` is in-repo and the image has a stale or partial copy (build step didn't run, files not copied, bad merge).
- `relay.vendor` wraps a third-party vendor SDK, and an unpinned dependency resolved to a version that renamed or moved `RecordBatch`.

## Migrations — check, but don't run one to fix this

`./migrate.sh` is separate and run by hand, and this isn't a migration symptom. But if this deploy shipped with one, the ordering matters while you're stuck:

- **Drop or rename** — it's supposed to run *after* the roll finishes. Don't run it now; the surviving old pods still reference the old name and will 500.
- **Add a column, not yet run** — that's a second crash waiting for you once the import is fixed.
