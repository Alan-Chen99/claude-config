# alan-writing-style/

Write, rewrite or check text as Alan. Single `SKILL.md`; nothing is loaded at runtime besides it.

## Files

| File       | What                                                                                        | When to read    |
| ---------- | ------------------------------------------------------------------------------------------- | --------------- |
| `SKILL.md` | The skill: jobs, scope, five habits (how he writes), kinds, form, errors policy, procedure | Using the skill |

| `samples/` | One sample = `NN-<name>.{context,ai,skill,human}.md`. ## Iteration

The skill is engineered from samples, not measured against a detector. Procedures used so far; pick per round rather than run as a checklist.

- Stages. Write the context first (facts, or the source verbatim, and the register); an opus agent with no skill writes `ai` from it; an opus agent that has read `SKILL.md` rewrites `ai` given the context, into `skill`; Alan edits a copy of `skill` (or writes from the context, as for 10 and 11) into `human`. Retention is the share of words in `human` that `skill` already had, by longest common subsequence over whitespace tokens; `git diff --no-index --word-diff` shows the same thing by eye. Target >= 80% where the piece is long enough for the number to mean anything; under about 50 words, and wherever the context was reconstructed (01, 03), compare the shape by eye (first sentence, labels, pointer or quote, one question) and treat the number as noise. Noise floor: two skill runs on the same input at `f9f741fb` overlapped 49-73% by the same measure, so a single run's retention is a coarse number. A sample line quoted in `SKILL.md` as an illustration makes that sample's regression worthless: at `599e7a41` rule 7 quoted the 06 reply and the 06 regression scored 100%; the quote was replaced by a description.
- Regression. After a rule change, rerun the skill on the samples the rule touches (with their contexts) and compare with `human`; a full rerun was the practice up to nine samples and is not needed since (Alan, 2026-09-23). Lower retention on an old sample is a question, not a failure: several rewrites can be right, so read the new output before changing anything back.
- Cross-domain. Contexts from outside this repo (hardware, household, a message to a person): a rule that only holds for software docs is overfitting.
- Context. The context is available material, not required content: for a README he answers questions about, Alan kept 13% of it (02) and two facts of six (04); for a shared wiki note he kept all of it (05). The brief must say the doc's function: who reads it, where it lives, what the reader has at hand, whether the doc or the writer answers questions. Alan read the first 02 brief as "make a standalone explanation to somewhere else", which is why that version quoted `build.yml` and the redo, a README section beside it, points to it instead. A topic Alan cannot judge gives no edit (04 filament). For a message, the context is the situation only, never a stance for him to voice (06). Copying from the context in the human stage is expected; a copied list is itself a style datum (05).
- Raw context. Contexts 01-09 are curated lists; in real use the agent starts from everything (a day's conversation log), so selection is the untested part. Alan's idea, 2026-09-23. Samples 10-12 are built on it: one synthetic session log (an opus agent wrote it from a course-of-the-day brief, told to leave in dead ends, tangents, verbose narration and terse user lines and to summarise nowhere), three functions from the same log (runbook section, status for people who were not there, message to a colleague), each brief stating the function only. What it showed: the ai stage invents mechanism the log does not carry (why a local file is reused, a rule for the order of backfills) and the skill stage kept it because the draft was its input, which is where the material-is-the-evidence rule comes from; a log's mid-day statements get carried past the step that changed them, by the skill and by Alan alike (11, the Postgres state); a brief that asks for a procedure the material only shows once gets a procedure from the agent and two measured facts from Alan. Retention is meaningless where he restructures (11: 22% at the same length); compare the parts by eye. Still untested: a real log, ten times longer, and a log Alan was actually in.
- Load. A 3,500-word log plus three pieces was too much for one round (Alan, 2026-09-23: "consider giving me less next; these took quite a long time to read+write"). A round is one piece, and material he already has in his head (his own session, this project) costs him nothing to read.
- Order. Messages before docs (Alan, 2026-09-23: "docs nowadays are also read by agents which makes it more complex and interleaved with prompt-engineering"). Message samples 06, 09, 12 ask; 14 answers, from the 10-12 material he already knows; 15 is to an outsider without the shared context (the supplier's contact), to see whether "no explanation of why" is a shared-context effect.
- Ask. Several rewrites can be right. When a rule is uncertain, ask Alan "A or B" with concrete text, or ask him to write the piece from a fixed context, rather than reading the answer off the prompt corpus.
- Ratings. Alan's idea, 2026-09-23: candidates written on past contexts, rated acceptable or not with a why, instead of edited. Cheaper for him than a human stage, gives a reason per verdict, gives negative cases for the check job, and unlike retention is neither order-sensitive nor surface. One file per round, `samples/ratings-NN.md`: per context two candidates from two skill versions, order shuffled, the key kept in the scratchpad (`round9/ratings-key.txt` for round 1) and written into the file after he has rated. A candidate identical to his human stage is not rated (06). A not-acceptable with its why is a rule datum; two acceptable candidates that differ are the record that several answers are right.
- Retention. LCS over words is order-sensitive and surface: the same six bullets reordered scored 29% (07, round 9 first draft), and 14 scores 32% in his own shape. A regression alarm, not the quality measure; ratings are.

A subagent testing a worktree's copy must `Read` that file: `~/.claude/skills` is a symlink to the canonical checkout, so invoking `/alan-writing-style` loads the installed version.

Retention, given `human` and `skill` files:

```python
import difflib, sys
def words(p):
    t = open(p).read()
    return (t[:t.index('\n---')] if '\n---' in t else t).split()  # Alan's comments follow a --- rule
a, b = words(sys.argv[1]), words(sys.argv[2])
kept = sum(m.size for m in difflib.SequenceMatcher(None, a, b, autojunk=False).get_matching_blocks())
print(f"{kept}/{len(a)} = {kept/len(a):.0%}")
```
