Yes — the ack flow is your read on them. Nothing else in the runbook is a live vendor signal.

**Primary: the `pending` → `sent` transition.** Records sit `pending` on hand-off and flip to `sent` only on their ack. So the vendor's liveness is exactly "are acks still arriving." Look at whether records handed off in the last few minutes are still `pending` — a whole recent cohort stuck is them; a single old one is a lost acknowledgement, which is what the runbook's one-hour rule is actually about. Don't use that hour as your outage threshold; it's a per-record diagnosis, not a detection window. (The runbook doesn't say where the pending queue is surfaced — assuming you can query it.)

**Second: the vendor admin console.** The runbook mentions it holds 1 of the 5 per-tenant pool connections, so you have a vendor-side surface that isn't the status page. If it responds, they're serving *something*. It doesn't prove the ingest API is up — separate surfaces fail separately — and the slot it consumes is already priced into the `WORKERS=4` ceiling, so using it costs nothing new.

**Don't read 503s as them yet.** Nearly always pool exhaustion; check `WORKERS` first. Only if it's at 4 and nothing extra is holding pool slots does a sustained 503 become weakly interesting.

**One redrive, not a probe loop.** `./redrive.sh <id>` on a single known-stuck record is sanctioned and gives you a live hand-off to watch. Do not batch or loop it — February, ~900 records, tenant rate-limited an hour, threshold unknown.

**Debug logging, conditionally.** It drops above ~2k lines/s. If the pipeline has actually stalled you're likely under that and it's usable; if volume is still flowing you'll lose the lines you turned it on for.

Two closing notes. Alerts predating the rename fire as `ledger-forwarder` — search both names. And there's no staging to test against, by decision, not oversight; standing that up is a finance conversation, not an outage workaround.

Worth flagging: `STRICT_ORDERING=0` exists because someone inferred vendor behavior from acks alone, never asked, never got it documented. You'd be reading the same channel. Whatever it shows, "vendor is down" is an inference — and with their status page dark, opening a direct line to them is probably the faster path to a fact.
