Impact analysis · ralph loop 3 · rounds 12–21 · 4 h 19 m

The 6000-Token Ceiling

One line in PROMPT.md caps the loop's own memory. Over ten iterations it held the notes flat to within 49 tokens — while a neighbouring file with no cap took on 1,234, some of it verbatim from what the cap deleted.

PROMPT.md · # Rules .ralph/agent/* ≤ 6000 tokens by agent-tools count-tokens. relocation is growth. Cut before add.

What the ten rounds did to the number

Net change +49 tokens across ten rounds, 5894 → 5943. The cap held.
Lines cut 1,552 against 1,548 written. Ten rounds of one-for-one exchange inside the directory.
Rounds ending over 5 / 10 measured by the rule's literal glob. Nobody noticed until round 19.
Uncapped neighbour +26% prompt-tests/SKILL.md, 4663 → 5897 tokens, absorbing deleted memories verbatim.

The short verdict

The rule works as a size control and fails as a growth control. Inside the directory it names, it is close to perfect: ten rounds of an agent that writes constantly ended 49 tokens heavier than they started, and the notes stayed legible. It bought that by making every round delete something, which turned out to be the only recurring review of carried state the loop had.

Outside the directory it names, the material did not stop existing. It moved. The clause meant to prevent that — relocation is growth — never fired: across the ten sessions, not one reasoning block applies it to a decision, while the skill file that received the displaced content grew by a quarter. And for eight of the ten rounds the loop was measuring itself with a narrower glob than the rule states, so half the rounds closed over the ceiling believing they were under it.

What it bought

P1

Flat notes under constant writing pressure

Each round drafts a critique, a milestone rationale, a result, decisions and memories. Git records 1,548 lines written into the directory over the run and 1,552 removed — the exchange the rule asks for, sustained for ten rounds, ending 49 tokens heavier than it started.

gross churn, 0f32e2ef..0ccb29b9: scratchpad +1037 −1026 · decisions +408 −397 · memories +98 −110 · summary +1 −15
in-round token peaks over each round's start: +715 (12) +536 (13) +289 (14) +409 (15) +660 (16) +329 (17) +634 (19) +603 (20) +756 (21) — about 4,930 tokens, a lower bound, since several rounds cut before they first measured.
P2

It produced a reusable compression method

The loop's most transferable output is a cut-order it wrote for itself, and it exists because something had to be deleted every round. It is the part of the scratchpad every later round kept.

scratchpad.md · "Durable method": cut in this order, stopping at the first class that is load-bearing — a claim (only claims can be wrong), a restatement, a duplicate of executable code (replace with its name), a trap (keep). Deletion is the default; each keep needs the argument.
P3

The forced re-read caught stale and false claims

Deleting requires reading, and reading the carried state against the round's new findings surfaced defects nothing else in the loop was checking for. Round 20 deleted two memories not as redundant but as contradicted by that round's own measurement, and said so in its report. Round 12, sweeping under budget pressure, found a memory citing a prompt-test case that had already been deleted, and rewrote it to drop the dead name.

iter20 required-notes: "unexpected change: six memories deleted rather than kept — two are contradicted by this round's measurement, not merely superseded."
P4

The pattern propagated to a file nobody capped

This is the result that speaks to the objective's own question — whether growth can be bounded without a human prescribing a number. Having lived under one, the loop wrote its own for the file it cared about, with no instruction to, and that file shrank.

self-imposed (contract): "A round that ships no prompt edit may not add a paragraph to sys_prompt/CLAUDE.md; it may replace one, and the replacement is shorter than what it replaced."
result: 7417 → 7227 tokens (−2.6%) across the run. The system prompt itself: 4261 → 4189.
P5

The audit number ended up somewhere immutable

Round 19 discovered that a token count written inside the counted files invalidates itself, and moved the figure to the commit message. Every round since closes with a dated, unrewritable statement of its own size — a better artifact than the in-file number ever was.

iter19 commit cf8f2dac: "Stating the token count inside .ralph/agent/ changes the count it states; the number goes in the round's last commit message instead. … = 5995, under the user's 6000."

What it cost

N1

Eight rounds measured something narrower than the rule

The rule names a tool, not a command, so each round invented one. Most used .ralph/agent/*.md, which silently drops tasks.jsonl — 193 to 505 tokens, 3–8% of the ceiling. Five of the ten rounds therefore closed above 6000 while reporting compliance. Round 19 was the first to run the literal glob, re-measured its predecessor's end state, and found the gap.

iter18 self-reported 5754. iter19 re-measured the same commit at 6122.
end-of-round totals, literal glob: 12 5834 · 13 6156 · 14 6159 · 15 6071 · 16 5926 · 17 6118 · 18 6122 · 19 5995 · 20 5550 · 21 5943
iter19 critique: "a hard user budget unmeasured and breached for two rounds … a rule with no command is what let two rounds miss it."
N2

The measurement is inside the thing measured

Recording the count, the commit range, or the ceiling rule itself changes the count. Round 19 spent six trimming passes on this: it committed at 5988, updated the heading with the commit hash it had just created, and was back at 6010. The fix — rewriting the contract line to say the number belongs in the commit message — was itself longer than the line it replaced and pushed the total to 6015, after which three unrelated paragraphs had to be cut to pay for it.

iter19 trace: 6122 → 6756 → 6248 → 6040 → 5988 → 6010 → 6015 → 6002 → 6003 → 5995. One pass intended as a cut ran one token long; the session noted "That actually lengthened it."
N3

"Relocation is growth" never once fired

The clause exists to stop the obvious evasion, and across all ten sessions it appears only where the harness pastes the rule in. No reasoning block applies it. Meanwhile the evasion it names is the loop's standard move: the most common stated reason for a deletion is that the content "already lives in the skill" or "already lives in sys_prompt/CLAUDE.md". Three such deletions can be matched to their arrival in the skill file, word for word.

deleted from memories.md under the cap → added to .claude/skills/prompt-tests/SKILL.md:
· the staged-diff leak fix → "--label before/<f> --label after/<f>"
· the probe-naming fix → "directory sharing a word with its own fixture is found by the ordinary search…"
· the probe-deletion rule → "A probe's directory is deleted by the round that wrote it"
SKILL.md over the run: 4663 → 5897 tokens (+1234).
N4

Roughly half the budget is spent on files the next round never sees

Only scratchpad.md is injected into the next iteration's prompt; memories.md is inject: manual and decisions.md is never injected by the harness at all. So the cap on the handoff channel is effectively 2,746 of a nominal 6,000, while the rest is taxed as archive. The two files the agent does not even author are taxed too — and the ceiling's last 56 tokens were spent, after the final round, by the harness summarizer writing a stale summary.md that says "No scratchpad found."

current split: scratchpad 2746 (46%) · memories 1639 (27%) · decisions 1349 (22%) · tasks 185 · summary 80
working tree now: 5999 / 6000. One token of headroom, consumed by a file no agent wrote.
N5

End-of-round trimming becomes word-level, at exactly the wrong moment

The housekeeping block sits last, next to the handoff the round is writing for its successor — so the cap binds hardest on the text whose quality matters most. Round 14 ran roughly fifteen measure-and-edit cycles, the last of them removing single words to cross the threshold. Across the run, 9–33 tool calls per round are budget work.

iter14 tail: 6035 → 6011 → 6004 → 6002 → 6000 → 5966 ("after 1 word dropped", "after 1 more word dropped").
budget-related tool calls: 33 (12) · 20 (13) · 28 (14) · 12 (15) · 13 (16) · 17 (17) · 9 (20) · 9 (21).
N6

Compression by line number, over a semantic contract

Round 17 compressed the loop history with head -110 — a cut chosen by position, not by meaning. It took the rounds 1–14 digest, the round 15 digest, and the whole round-16 section, including the (instruction) block round 16 had written for round 17. The instruction was read before it was destroyed, but the record that would let a later round check whether 17 complied went with it. Rounds do re-derive from git when they notice a gap — round 17 reconstructed a case's entire run history with git log — which is recovery, at a cost.

head -110 .ralph/agent/scratchpad.md > /tmp/sp.md && append 16-line "History — rounds 1–16" && cp /tmp/sp.md .ralph/agent/scratchpad.md
N7

It contradicts the harness contract, and the conflict was never resolved

The scratchpad directive the harness injects says to append; the user rule says to cut. Round 16 identified the conflict precisely, decided it alone, and reported it in a closing note — one line in a final turn, in a run of ten. No round wrote a contract clause resolving it, and nothing raised it where a human would see it.

iter16 required-notes: "the between-worker contract says 'always append' to the scratchpad while the user caps .ralph/agent/* at 6000 tokens. Those conflict; the budget wins … Worth an explicit (contract) line if a later round trips on it."

The one that cuts both ways

The rule is the thing the objective is trying to avoid

The task asks that documentation stop growing without a human setting or prescribing a size limit. The loop's own notes are the one surface where a human set one — so the strongest anti-growth result in the run comes from the mechanism the objective rules out, and says nothing about whether the agent would have bounded itself unaided.

And it is also the only evidence that self-limiting works

Having worked under a number, the loop wrote an unprescribed rule of the same shape for sys_prompt/CLAUDE.md — replace, don't append; the replacement is shorter — and that file fell 2.6% while the file governed by nothing rose 26%. The prescribed limit did not answer the question, but it did demonstrate the pattern the answer would need.

If the rule stays

  1. Name the command, not the tool. Eight rounds measured a narrower set than the rule states because each had to invent the invocation; the one that wrote the command down ended the breach.
  2. Exclude what the agent does not write. tasks.jsonl and summary.md are harness output, the CLI cannot prune the first, and together they took the last 250 tokens of headroom.
  3. Cap the handoff, not the archive — or cap them separately. Half the budget currently constrains files the next round is never shown.
  4. Put a ledger on the destinations. relocation is growth is unenforceable as written and fired zero times; the skill file grew 26% while the capped directory stood still.
  5. Forbid the number inside the counted set. Round 19 derived this the hard way; it belongs in the rule, not in a contract line the next cleanup may cut.

Method. Five session-analysis subagents in evidence mode over the ten iteration transcripts (06fa1252, b52a94fd, 76383586, 05117af2, 8cbdf6ab, cdcc1497, 08ce9bfe, 9bb51163, 122b4216, 2328f962), one focus: everything touching the ceiling. Every quoted count is a tool result from a transcript or a re-measurement here. Rounds 16–17 were extracted on Opus 5; the other four pairs on Sonnet, after the Opus dispatches returned an API safeguard error — extraction depth may differ between them.

Measured here. for f in scratchpad decisions memories summary tasks; do git show <sha>:.ralph/agent/$f | agent-tools count-tokens --file /dev/stdin; done at all 60 commits touching the directory; the same for sys_prompt/CLAUDE.md, sys_prompt/alan-default-next.md and .claude/skills/prompt-tests/SKILL.md at each round boundary. Local tokenizer, not --api — the backend the rule's bare count-tokens selects, and the one every round used.

Not measured. Whether the deleted material was ever needed again; only two re-derivations are on record, and a round that silently lacked something would leave no trace. How much of the skill file's +1234 tokens is displaced .ralph content: three deletions match their arrival word for word, the rest is independent instrument work. What the directory would have done with no cap — the churn figures show what was exchanged, not what would have been kept. Repo-wide the run was still deletion-positive: −1608 lines.
